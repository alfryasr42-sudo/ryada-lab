# مختبر ريادة — تطبيق المندوب الميداني

تطبيق Flutter يعمل على Android وiPhone، مخصص لمندوب المختبر الميداني:

1. مزامنة مرضى اليوم من سيرفر المختبر.
2. مسح باركود العينة للوصول إلى المريض والتحاليل المطلوبة.
3. تصوير ورقة النتائج وقراءة الأرقام آلياً (OCR).
4. مراجعة كل قيمة وتصحيحها يدوياً مع تنبيه للقيم غير الطبيعية.
5. حفظ النتائج محلياً وإرسالها للسيرفر، مع إعادة محاولة الإرسال عند انقطاع الشبكة.

> التطبيق لا يعتمد على اتصال دائم. المصدر المحلي للحقيقة أثناء العمل الميداني هو
> SQLite على الجهاز، والسيرفر يُزامَن عند توفّر الشبكة.

## البنية

```text
lib/
├── main.dart                     # نقطة التشغيل والثيم العربي RTL
├── models/
│   ├── patient_model.dart        # المريض + التحاليل المطلوبة + كتالوج التحاليل
│   └── result_model.dart         # النتائج النهائية وحزمة الإرسال
├── services/
│   ├── database_service.dart     # SQLite: المرضى والنتائج والمسودات
│   └── api_service.dart          # GET للمزامنة وPOST للإرسال + الإعدادات
├── views/
│   ├── home_screen.dart          # مزامنة اليوم وقائمة المرضى والإحصائيات
│   ├── scan_screen.dart          # الباركود + الكاميرا + OCR
│   └── review_screen.dart        # المراجعة والتعديل والاعتماد والإرسال
└── utils/
    ├── app_format.dart           # تنسيق التاريخ والأرقام بالعربية
    └── ocr_parser.dart           # استخراج الأرقام وتوزيعها على التحاليل
```

قاعدة البيانات المحلية:

- `patients`: بيانات المريض والتحاليل المطلوبة وحالة العمل.
- `results`: مسودة/نتيجة واحدة لكل مريض مع حالة `synced` ومعرّف السيرفر.
- حالات المريض: `pending` → `in_progress` → `completed` (محفوظ محلياً) → `synced`.
- إعادة المزامنة لا تُلغي مسودة أو نتيجة أُرسلت محلياً.

## التشغيل

### التشغيل بنقرة مزدوجة (Windows)

- انقر نقراً مزدوجاً على اختصار **Riada Lab** على سطح المكتب، أو على `Run-RiadaLab.bat`.
- في أول تشغيل يثبّت المشغّل تلقائياً Flutter وJava 17 وAndroid SDK، ثم يبني التطبيق.
- إذا كان هاتف أندرويد موصولاً ومفعّلاً عليه USB Debugging فسيُثبّت التطبيق ويُشغّل مباشرة.
- إذا لم يوجد هاتف فسيُنشأ `build\app\outputs\flutter-apk\app-release.apk` ويُفتح مجلده.
- لبناء APK فقط انقر `Build-APK.bat`.
- يتطلب اتصال إنترنت في المرة الأولى، ومساحة قرص تقارب 3 غيغابايت.
- تُخزَّن أدوات البناء والذاكرات المؤقتة في `D:\RiadaLabTools` و`D:\Android` و`D:\RiadaLabCaches` لتجنب امتلاء القرص `C:`.
- iOS يحتاج macOS وXcode؛ لا يمكن بناؤه من Windows.

### المحاكي على الكمبيوتر

- تم تثبيت Android Emulator وصورة Android 15 (x86_64) وإنشاء جهاز افتراضي باسم `RiadaPhone`.
- اختصار **Riada Emulator** على سطح المكتب يشغّل المحاكي.
- عند النقر على **Riada Lab** بدون هاتف موصول، يبدأ المحاكي تلقائيًا ثم يثبّت التطبيق ويشغّله.
- بيانات المحاكي في `D:\Android\Avd`.

### المتطلبات

- Flutter SDK حديث (Dart 3.3 أو أحدث).
- Android SDK (Compile SDK 34/35) أو Xcode 15+ مع CocoaPods.
- جهاز حقيقي يُفضّل للكاميرا. كاميرا iOS Simulator غير متاحة.

## إعداد السيرفر في التطبيق

من الشاشة الرئيسية → أيقونة الإعدادات:

| الحقل | مثال | ملاحظات |
|---|---|---|
| عنوان السيرفر | `http://192.168.1.10:8000` | إذا لم تكتب `http://` سيُضاف تلقائياً |
| معرّف المختبر | `LAB-01` | يُرسل مع كل نتيجة |
| اسم المندوب | `يوسف` | يُرسل مع كل نتيجة |
| مفتاح API | اختياري | يُرسل كـ `X-API-Key` |

كل الإعدادات تُخزّن محلياً على الجهاز فقط. بدون عنوان سيرفر يعمل التطبيق في
وضع البيانات التجريبية والمسودات المحلية.

### فحص الاتصال

- من الإعدادات: زر **فحص السيرفر** يختبر `GET /healthz`، وزر **فحص API**
  يختبر `GET /api/patients` بالمفتاح المدخل.
- في الشاشة الرئيسية: ثلاث أيقونات صغيرة للسيرفر وAPI والذكاء، خضراء عند
  الاتصال وحمراء عند الفشل، وبيضاء قبل انتهاء الفحص.
- مؤشر **الذكاء** يقيس جاهزية محرك OCR المحلي (ML Kit) وليس خدمة ذكاء
  خارجية. لإضافة فحص لخدمة مثل Groq/OpenAI نحتاج عنوانها ومفتاحها.

## عقد الـ API المتوقع

التطبيق يستدعي واجهتين فقط. يجب أن يوفّرهما سيرفر المختبر.

### 1) جلب مرضى اليوم

```http
GET {baseUrl}/api/patients?date=2026-11-05
Accept: application/json
X-API-Key: <optional>
```

الاستجابة المقبولة: قائمة مباشرة، أو كائن يحتوي `data` أو `patients` أو `items`.

```json
{
  "success": true,
  "data": [
    {
      "id": "V-1001",
      "name": "أحمد محمد العتيبي",
      "age": 42,
      "gender": "male",
      "phone": "0555001122",
      "barcode": "R-1001",
      "visit_date": "2026-11-05",
      "notes": "صيام 10 ساعات",
      "tests": [
        "CBC",
        {
          "code": "HGB",
          "name": "Hemoglobin",
          "unit": "g/dL",
          "ref_min": 12,
          "ref_max": 16
        },
        {
          "test_code": "GLU",
          "test_name": "Fasting Glucose",
          "unit": "mg/dL",
          "reference_range": "70 - 110"
        }
      ]
    }
  ]
}
```

- `tests` يقبل قائمة نصوص (مثل `CBC`) أو كائنات. أسماء الحزم المعروفة
  (`CBC`, `LIPID`, `LFT`, `KFT`, `THYROID`, `ELECTROLYTES`) تُوسَّع تلقائياً
  إلى تحاليلها باستخدام الكتالوج المحلي.
- إذا لم يُرسل السيرفر الوحدة أو المجال المرجعي، يستخدم التطبيق الكتالوج المحلي.
- الحقول البديلة المدعومة: `patient_id`, `patient_name`, `sample_id`,
  `accession`, `date`, `requested_tests`, `analyses`.
- القيم غير المألوفة (تحليل غير موجود في الكتالوج) تُقبل كما هي وتظهر
  بلا مجال مرجعي، ويستطيع المندوب إدخال النتيجة يدوياً.

### 2) إرسال النتيجة

```http
POST {baseUrl}/api/results
Content-Type: application/json
X-API-Key: <optional>
```

```json
{
  "lab_id": "LAB-01",
  "operator": "يوسف",
  "result": {
    "patient_id": "V-1001",
    "barcode": "R-1001",
    "visit_date": "2026-11-05",
    "captured_at": "2026-11-05T10:42:13.000",
    "notes": "تمت المراجعة",
    "operator": "يوسف",
    "results": [
      {
        "test_code": "HGB",
        "test_name": "Hemoglobin",
        "value": 11.2,
        "text_value": null,
        "unit": "g/dL",
        "ref_min": 12,
        "ref_max": 16,
        "flag": "low",
        "confidence": 0.95,
        "raw_text": "hemoglobin 11.2 g/dl 12 - 16"
      },
      {
        "test_code": "VITD",
        "test_name": "Vitamin D",
        "value": null,
        "text_value": "Negative",
        "unit": "ng/mL",
        "ref_min": 30,
        "ref_max": 100,
        "flag": "unknown",
        "confidence": 1.0,
        "raw_text": null
      }
    ]
  }
}
```

`flag` واحد من: `normal`, `high`, `low`, `critical_high`, `critical_low`, `unknown`.

الاستجابة الناجحة (2xx):

```json
{ "success": true, "id": "RES-7781" }
```

التطبيق يقرأ معرّف الإرسال من `id` أو `result_id` أو `submission_id` أو
`reference` أو من `data`، ثم يعلّم النتيجة `synced` محلياً. إذا كانت الاستجابة
`{"success": false, "message": "..."}` أو رمز HTTP خارج 2xx، تبقى النتيجة
محفوظة محلياً وتظهر رسالة خطأ بالعربية.

### 3) الملخص المالي (قراءة فقط)

```http
GET {baseUrl}/api/finance/summary?from=2026-11-01&to=2026-11-05
X-API-Key: <optional>
```

يمكن استخدام `date=2026-11-05` ليوم واحد، أو `from` و`to` لفترة (الحد 92 يومًا).
يعيد رصيد الصندوق الحالي، وملخص الفترة بترتيب ورقة «دخل اليوم»:
عدد الحالات، إجمالي المبيعات، الخصومات، صافي المبيعات، المقبوض من الاستقبال،
ديون الفترة، ديون سابقة محصّلة، المدفوع الإلكتروني، المصاريف، ثم حركة الصندوق
(قبض/صرف نقدي وإلكتروني والصافي)، وقائمتي المقبوضات والمصروفات، والديون
وأعلى 10 مدينين. لا يكتب أي بيانات.

لعرضه في التطبيق: أيقونة المحفظة في الشاشة الرئيسية، ثم اختر «اليوم» أو
«هذا الأسبوع» أو «هذا الشهر» أو حدّد «من/إلى» يدويًا.

لحماية القراءة على الشبكة المحلية، عيّن `RIADA_MOBILE_API_KEY` في `.env`
وأدخل نفس القيمة في حقل مفتاح API داخل التطبيق. إذا لم يُعيَّن، تبقى الواجهة
مفتوحة لمن يستطيع الوصول للمنفذ.

### 4) المخزن (قراءة فقط)

```http
GET {baseUrl}/api/store/summary?q=&window=5
X-API-Key: <optional>
```

يعيد مؤشرات المخزن (عدد المواد، قيمة المخزون، تحت الحد الأدنى، منتهية
الصلاحية، النفاذ المتوقع، غير المقيّمة)، وقائمة المواد مع دفعاتها وصلاحياتها،
والنواقص المقترح شراؤها، وتنبيهات المخزن. `q` للبحث باسم المادة أو الرمز أو
رقم الدفعة، و`window` عدد أيام تغطية النواقص (1–30، الافتراضي 5).
لا يكتب أي بيانات.

لعرضه في التطبيق: أيقونة المخزن في الشاشة الرئيسية.

### 5) المرضى الحرجة (قراءة فقط)

```http
GET {baseUrl}/api/critical?from=2026-11-01&to=2026-11-06
X-API-Key: <optional>
```

يعيد الزيارات التي تحتوي نتائج خارج المعدل (`low`/`high`) خلال الفترة
(الحد 92 يومًا، والافتراضي اليوم)، مع كل نتيجة حرجة وقيمتها ومعدلها،
**ومن أدخل النتيجة** (`entered_by`)، و**من طبع التقرير** (`printed_by`
و`printed_at` من سجل تسليمات التقرير)، وحالة الطباعة. لا يكتب أي بيانات.

لعرضه في التطبيق: أيقونة القلب في الشاشة الرئيسية.

### 6) الاستقبال (قراءة فقط)

```http
GET {baseUrl}/api/reception/summary?date=2026-11-06
X-API-Key: <optional>
```

يعيد زيارات اليوم مع حالة كل زيارة، بيانات المريض والطبيب والباركود،
والمبالغ (الإجمالي/الخصم/الصافي/المدفوع/المتبقي)، وعدد الفحوصات والجاهز منها،
ومؤشرات اليوم (عدد الزيارات، قيد التنفيذ، مكتملة، غير مدفوعة، المحصّل، الديون).
لا يكتب أي بيانات.

لعرضه في التطبيق: أيقونة الاستقبال في الشريط العلوي.

**استقبال مريض وتسوية مالية (كتابة):**

```http
GET  {baseUrl}/api/reception/catalog?q=
GET  {baseUrl}/api/reception/patients?q=
POST {baseUrl}/api/reception/visit
POST {baseUrl}/api/reception/pay
```

- `catalog`: الفحوصات النشطة وأسعارها وقائمة الأطباء.
- `patients`: بحث سريع عن مريض موجود بالاسم أو الجوال.
- `visit`: ينشئ مريضاً جديداً (أو يستخدم `patient_id`) وزيارة بفحوصاتها،
  ويحسب الإجمالي/الخصم/الصافي/المدفوع/المتبقي، ويسجّل الدفعة في دفتر
  المالية ويخصم مواد المخزون.
- `pay`: تسوية زيارة (`visit_id`) أو دين مريض (`patient_id`).

الطلبات تُرسل JSON، وتُرجع `success` و`data`. الكتابة تتم مباشرة في قاعدة
RiadaLab لتظهر في شاشات المختبر والمالية.

### 7) ترخيص تطبيق الهاتف

```http
POST {baseUrl}/api/mobile/request
GET  {baseUrl}/api/mobile/status?device_id=&request_code=
POST {baseUrl}/api/mobile/heartbeat
```

- التطبيق يولّد `device_id` ثابتاً لكل نسخة، ويعرض `request_code` مثل
  `MOB-AB12-CD34`.
- المستخدم يرسل الطلب من شاشة التفعيل، ثم يوافق المدير من صفحة الموقع:
  `/mobile-licenses/` ويحدد النوافذ المسموحة.
- بعد الموافقة يصدر السيرفر `token`، ويرسله التطبيق في الترويسة
  `X-Device-Token` مع كل طلب API.
- الصلاحيات: `sync`، `finance`، `store`، `critical`، `reception`.
- صفحة الإدارة تتيح الاعتماد، الرفض، تعديل الصلاحيات، وإلغاء الترخيص.
- لفرض الرمز على كل واجهات API عيّن `RIADA_REQUIRE_DEVICE_TOKEN=1`؛
  عندها تُرفض أي نسخة غير معتمدة (تبقى مسارات `/api/mobile/` مفتوحة
  لطلب الترخيص).

### الوصول من الهاتف

السيرفر يستمع افتراضياً على `0.0.0.0:8080`، لكن جدار حماية Windows قد يمنع
الاتصال من الهاتف.

**على نفس شبكة Wi-Fi:**

1. شغّل `start_lan_access.bat` (أو `scripts\server_access.ps1`).
2. وافق على نافذة UAC لفتح المنفذ 8080.
3. سيظهر عنوان مثل `http://192.168.1.10:8080` — أدخله في شاشة التفعيل.

**من شبكة أخرى أو بيانات الجوال (الجسر العالمي):**

شغّل `start_bridge.bat`، وسيُنزّل `cloudflared` مرة واحدة ثم يفتح نفقاً
عاماً دائماً ويعيد تشغيله تلقائياً عند الانقطاع. يكتب الرابط في
`public_url.txt` ويقرأه التطبيق من `/api/bridge/info` ليحفظه كعنوان عام.

**الجسر التلقائي في التطبيق:**

- الإعدادات تحتوي حقلين: **عنوان السيرفر المحلي** و**عنوان API العام**.
- يبدأ التطبيق بالمحلي، وإذا فشل خلال 7 ثوانٍ يعيد الطلب نفسه على العنوان
  العام تلقائياً، والعكس عند تعذّر العام.
- عند فتح التطبيق وهو متصل محلياً يقرأ `/api/bridge/info` ويحدّث العنوان
  العام تلقائياً، فلا حاجة لإدخال رابط النفق يدوياً.
- زرا **محلي / عام** في الإعدادات للتبديل اليدوي.

```http
GET {baseUrl}/api/bridge/info
```

يُعيد `public_url` و`lan` وقيمة `tunnel` وحالة التحديث.

### ملاحظات تكامل

- سيرفر RiadaLab المحلي يوفّر الآن `/api/patients` و`/api/results` عبر حزمة
  `api/`، ويقرأ ويكتب مباشرة في قاعدة `lis.sqlalchemy.db`. شغّله بـ`start_riada.bat`
  ثم اضبط عنوان السيرفر في التطبيق.
- المحاكي يستخدم `http://10.0.2.2:8080` افتراضيًا. على الهاتف الحقيقي استخدم
  عنوان IP للكمبيوتر مثل `http://192.168.1.10:8080`.
- سُمح بـHTTP العادي في نسخة الاختبار عبر `usesCleartextTraffic="true"`.
  للإنتاج استخدم HTTPS أو `networkSecurityConfig` يسمح بالعنوان المحلي فقط.
- باركود العينة يجب أن يطابق حقل `barcode` القادم من السيرفر. الأنماط
  المدعومة في المسح: Code 128, Code 39, Code 93, EAN-13, QR, ITF.
- لا تُرسل صور المرضى إلى السيرفر؛ تُحفظ الصورة محلياً فقط كمرجع للمراجعة.
  أضف رفع الصور لاحقاً إذا كان مطلوباً في سجلك.

## سير العمل الميداني

1. **مزامنة اليوم** من الشاشة الرئيسية (أو اختيار يوم آخر من أيقونة التقويم).
2. اختيار المريض من القائمة أو **مسح الباركود**.
3. تصوير ورقة النتائج. يُشغّل OCR الإنجليزي/الأرقام ثم يفتح شاشة المراجعة.
4. مراجعة القيم. القيم ذات الثقة المنخفضة معلّمة، وكل تعديل يدوي يرفع الثقة إلى 100%.
5. **مسودة** لحفظها محلياً، أو **اعتماد وإرسال**.
6. عند فشل الشبكة تبقى النتيجة مسجلة، ويظهر شريط «إرسال الكل» في الرئيسية.

### حدود OCR

- محرّك Google ML Kit المستخدم يدعم النص اللاتيني والأرقام، وليس النص العربي.
  أسماء التحاليل العربية تُفهم عند إدخالها يدوياً، بينما ورقة النتائج الإنجليزية
  هي المسار الآلي الأساسي.
- التطبيق يزيل التواريخ والوحدات والمجالات المرجعية قبل قراءة الأرقام، ويحاول
  اختيار الرقم الواقع داخل المجال. عند غياب اسم التحليل يوزّع الأرقام بالترتيب
  على التحاليل المتبقية بثقة منخفضة (45%) لتنبيه المندوب للمراجعة.
- المراجعة البشرية إلزامية قبل الإرسال. لا تعتمد النتائج آلياً في قرار طبي.

## الخصوصية والأمان

- البيانات الصحية محفوظة في SQLite داخل مساحة التطبيق الخاصة.
- لا يتم إرسال أي بيانات إلا عند الضغط على «اعتماد وإرسال» أو «إرسال الكل».
- مفتاح API يُخزّن في SharedPreferences. للإنتاج يُفضّل تخزينه في
  `flutter_secure_storage` وتفعيل شهادة TLS مثبتة (certificate pinning) إذا
  كان السيرفر عاماً.
- فعّل قفل الجهاز وسیاسة مسح البيانات عند فقدانه.

## استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| «لم يتم ضبط عنوان السيرفر» | الإعدادات من الشاشة الرئيسية |
| الكاميرا سوداء | صلاحية الكاميرا من إعدادات النظام؛ جرّب جهازاً حقيقياً |
| OCR لا يجد أرقاماً | صورة أوضح، إضاءة أقوى، تصوير الورقة كاملة من الأعلى |
| فشل الإرسال | النتيجة محفوظة؛ تحقق من عنوان السيرفر ثم «إرسال الكل» |
| لا يظهر مريض بعد المسح | اضغط مزامنة اليوم أولاً؛ الباركود يجب أن يطابق حقل `barcode` |
| iOS لا يبني | نفّذ `pod install` داخل `ios/` وتأكد من إعدادات التوقيع |
| Pod install يطلب إصدار iOS أعلى | ML Kit يحتاج iOS 12+؛ فعّل `platform :ios, '12.0'` في `ios/Podfile` واستبعد `armv7` عند الحاجة |
